# 真实数据集适配说明

本项目已经支持从真实班级数据中逐步导入学生、课程和成绩。推荐导入顺序为：

1. 先导入学生基础信息
2. 再维护或导入课程信息
3. 最后导入成绩数据

这样可以保证成绩导入时能够正确校验学号、课程编号、班级、学期和考试批次。

如果原始数据集不是系统标准模板，可先运行规则识别版智能 Excel 适配器。说明见 `docs/智能Excel适配器说明.md`。适配器会生成标准模板和转换报告，不写数据库，也不会自动确认导入。

默认命令：

```bash
python backend/scripts/convert_score_test_excels.py
```

默认输出目录：

```text
Score test/converted/
```

## 1. 学生基础信息导入模板

当前 MVP 支持 `.xlsx` 文件，第一行必须为表头。
模板细节也可查看 `docs/学生基础信息批量导入模板说明.md`。

必填字段：

| 中文表头 | 英文字段 | 说明 |
|----------|----------|------|
| 学号 | student_id | 写入 `users.user_id` |
| 姓名 | real_name / student_name | 写入 `users.real_name` |
| 班级 | class_name | 写入 `users.class_name` |

可选字段：

| 中文表头 | 英文字段 | 说明 |
|----------|----------|------|
| 用户名 | username | 为空时默认使用学号 |
| 年级 | grade | MVP 中仅用于预览展示，不写入当前表结构 |
| 学校 | school_name | MVP 中仅用于预览展示，不写入当前表结构 |
| 性别 | gender | MVP 中仅用于预览展示，不写入当前表结构 |
| 手机号 | phone | MVP 中仅用于预览展示，不写入当前表结构 |
| 初始密码 | password | 为空时默认 `123456` |

示例：

| 学号 | 姓名 | 班级 | 用户名 | 初始密码 |
|------|------|------|--------|----------|
| S101 | 张三 | 2025级1班 | S101 | 123456 |
| S102 | 李四 | 2025级1班 |  |  |

导入规则：

- 所有导入用户固定为 `student` 角色。
- `status` 默认写入 `1`，即启用。
- `preview` 阶段只解析和校验，不写入数据库。
- `confirm` 阶段只导入合法且数据库中不存在的学生。
- 已存在的学号会标记为 `duplicate`，确认导入时跳过。
- 用户名已存在但学号不存在时会标记为错误，避免账号冲突。

## 2. 成绩导入模板

成绩导入已经支持 `.xlsx`，字段如下：

必填字段：

| 中文表头 | 英文字段 |
|----------|----------|
| 学号 | student_id |
| 课程编号 | course_id |
| 分数 | score |
| 考试日期 | exam_date |
| 考试批次 | exam_batch |

可选字段：

| 中文表头 | 英文字段 |
|----------|----------|
| 学期 | term |
| 姓名 | student_name |
| 课程名称 | course_name |

成绩导入前必须先存在对应学生和课程，否则会在预览阶段返回行级错误。

## 3. 宽表转长表建议

很多学校导出的成绩表是宽表，例如：

| 学号 | 姓名 | 班级 | 数学 | 英语 | 语文 |
|------|------|------|------|------|------|
| S101 | 张三 | 2025级1班 | 88 | 92 | 85 |

当前成绩导入接口要求长表：

| 学号 | 课程编号 | 分数 | 考试日期 | 考试批次 |
|------|----------|------|----------|----------|
| S101 | MATH01 | 88 | 2026-04-10 | 期中 |
| S101 | ENG01 | 92 | 2026-04-10 | 期中 |
| S101 | CHN01 | 85 | 2026-04-10 | 期中 |

建议在 Excel 中使用 Power Query、透视逆操作，或用脚本把各学科列转换为多行后再导入。

## 4. `/api/options` 与真实数据

通用候选项接口 `/api/options` 已从数据库读取真实数据：

- students、student_names、classes 来自 `users`
- courses、course_ids、terms 来自 `courses`
- exam_batches 来自 `scores` 并合并常用默认值
- teachers 来自 `users` + `roles`

学生账号只返回和自己相关的课程、学期和考试批次；教师和管理员返回更完整的管理候选项。导入真实学生后，班级、学生列表和姓名候选项会自然更新。

## 5. 课程导入后续规划

课程批量导入暂未在本轮实现。推荐后续增加：

- `POST /api/courses/import/preview`
- `POST /api/courses/import/confirm`

字段：

| 中文表头 | 英文字段 | 必填 |
|----------|----------|------|
| 课程编号 | course_id | 是 |
| 课程名称 | course_name | 是 |
| 任课教师 | teacher_id | 否 |
| 学期 | term | 否 |
| 学分 | credit | 否 |

规则：

- 仅管理员可导入课程。
- preview 阶段校验课程编号是否重复、教师是否存在、学分是否为数字。
- confirm 阶段跳过重复课程，不覆盖已有课程。
- 不影响现有单条课程管理功能。

## 6. 未来学校字段扩展

当前 `users` 表没有 `grade`、`school_name`、`gender`、`phone` 字段，本轮不修改数据库结构。如果后续需要长期保存这些字段，建议新增用户资料扩展表或在一次明确迁移中扩展 `users` 表，并提供幂等迁移脚本。

## 导入后的追踪与撤销

`converted_k12` 产物仍按“学生 -> 课程 -> 成绩”顺序人工预览和确认。新版本每次 confirm 返回 `import_batch_id`。批次撤销不会删除账本：未修改的新成绩逻辑删除；未修改且无业务引用的新学生安全停用；有后续修改或引用时跳过并返回原因。
