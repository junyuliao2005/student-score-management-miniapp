# 试卷图片识别技术说明

## 当前链路

```text
选择图片
-> 安全上传
-> 扩展名/MIME/大小/文件签名/像素校验
-> EXIF 方向修正和去除元数据
-> OCR 预览
-> 用户修改识别文字
-> 用户确认
-> 隐私脱敏
-> DeepSeek 或 Mock/Fallback
-> 结构化结果
-> 审计日志
-> 删除临时 OCR 预览
```

原始图片不写入公开目录，也不长期保存到后端磁盘。后端只保存最多 30 分钟、按操作者隔离的 OCR 文本预览，确认分析后在 `finally` 中删除。

## Provider

- `LocalOCRProvider`: 使用 RapidOCR，只有在可选 OCR 环境安装成功并设置 `OCR_PROVIDER=local` 时启用。
- `MockOCRProvider`: 不伪造识别文字，明确提示用户手动录入/粘贴后再确认分析。
- `CloudOCRProvider`: 当前未实现，不声明为已支持。

## Python 兼容性

当前本机项目虚拟环境为 Python 3.14，检查时没有安装 Pillow、RapidOCR 或 ONNX Runtime。普通 Flask 后端不在模块导入时强制加载 OCR 依赖，因此登录、成绩、统计等功能不受影响。

推荐使用 Python 3.11 或 3.12 建立独立 OCR 环境：

```powershell
cd backend
powershell -ExecutionPolicy Bypass -File scripts/setup_ocr_env.ps1
```

依赖文件为 `backend/requirements-ocr.txt`。本地安装成功后设置：

```env
OCR_PROVIDER=local
OCR_FALLBACK_ENABLED=true
```

## API

- `POST /api/ai/exam-paper/ocr-preview`: multipart 上传图片，返回 OCR 文字、置信度、Provider、模式和警告。
- `POST /api/ai/exam-paper/analyze-ocr`: 传入 `ocr_id` 和用户修正文字，再执行 AI 分析。
- 旧 `/api/ai/exam-paper/analyze-image` 保留兼容，但推荐新两阶段链路。

## 状态和不确定性

前端包含选择、上传进度、OCR 预览、手工修改、确认分析、结构化结果、失败提示和重试。OCR 不可用或低置信度时必须显示警告；不确定内容不由系统凭空补齐。

## 验证

```bash
cd backend
python scripts/test_ocr_pipeline.py
```

无 Pillow 时脚本显示 `SKIPPED`；有 Pillow 时使用本地生成图片和 Mock OCR/AI，不调用外部 API。
