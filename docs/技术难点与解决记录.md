# 技术难点与解决记录

## 1. 成绩隐私边界

问题：角色权限只能判断“能否访问接口”，不能表达教师班级/课程范围和学生 published 状态。

解决：后端引入显式教师绑定表与统一 scope service；学生和家长查询复用考试发布匹配逻辑。无绑定默认拒绝，前端参数不能扩大范围。

## 2. 大统计阻塞

问题：全模型 `.all()` 和关系 eager loading 会产生角色/权限大联表，单 worker 被长查询拖住。

解决：统计只选择必要字段、SQL 聚合、明确考试批次、分页/窗口排名；前端按标签懒加载并阻止重复请求。

## 3. 可撤销导入

问题：简单记录导入 ID 无法判断数据是否被后续人工修改，直接删除会破坏真实数据。

解决：confirm 同事务写业务记录、批次和安全前后快照。撤销前比较当前值与 after snapshot；不一致或存在业务引用时跳过，成绩逻辑删除、用户安全停用，账本永久保留。

## 4. 小程序云端文件上传

问题：体验版普通 API 使用 `callContainer`，传统 `wx.uploadFile` 依赖合法域名。

解决：统一上传工具在 cloud 模式先上传私有 CloudBase 文件，再由后端消费短期 URL；后端限制 HTTPS、443、受信域名、大小和重定向，并在前端 finally 删除云文件。

## 5. OCR 与文本模型边界

问题：DeepSeek 文本模型不应直接接收图片，OCR 误识别也不能直接进入分析。

解决：图片真实解码 -> OCR 预览 -> 用户修改 -> 确认分析。预览按用户隔离、30 分钟过期、确认或失败后清理。

## 6. 可验证而不碰生产数据

问题：真实 MySQL 包含学生数据，自动化测试不能初始化或清理。

解决：TestConfig 使用 SQLite 内存库；外部 HTTP 使用假客户端；DeepSeek 无 Key 显示 SKIPPED；迁移脚本仅创建指定表并静态检查无 DROP/TRUNCATE/DELETE。
