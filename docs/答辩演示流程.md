# 答辩演示流程

## 总时长：约 8-10 分钟

---

## 1. 项目介绍（1 分钟）

**开场白：**

> 各位老师好，我的课题是"学生成绩管理小程序 + AI 学情诊断辅助系统"。
>
> 本系统采用微信小程序前端 + Flask 后端 + MySQL 数据库的三层 B/S 架构，实现了成绩管理的核心功能，并集成了 AI 学情分析作为亮点功能。
>
> 系统支持三种角色：学生、教师和管理员，覆盖了成绩录入、统计排名、等级评定、自动评语、低分/偏科预警、AI 学习建议等 7 大功能模块。

**关键数据：**
- 后端 22 个 RESTful API 接口
- 小程序 14 个页面
- 11 张数据库表
- 19 个权限点的 RBAC 控制
- AI 模块支持 mock 演示，无需真实 API Key

---

4. 说明：支持多条件组合筛选和分页

## 5. 技术架构说明（1 分钟）

### 5.1 后端架构

```
Flask Application Factory
├── models/ (SQLAlchemy ORM, 11张表)
├── routes/ (Blueprint, 7个模块)
├── services/ (业务逻辑层)
├── middleware/ (JWT/权限/trace/错误处理)
└── utils/ (工具层)
```

### 5.2 前端架构

```
微信小程序原生开发
├── utils/ (request/auth/permission封装)
├── pages/ (14个页面)
└── components/ (8个组件)
```

### 5.3 关键技术点

- **认证**: JWT (PyJWT, HS256, 2小时过期)
- **权限**: 简化 RBAC (5表模型, 19个权限点)
- **排名**: 竞赛排名算法 (同分同名次, 1,1,3)
- **AI**: 策略模式 (mock/real provider), 默认 mock
- **响应**: 统一 JSON 格式 `{code, message, data, trace_id}`

## 6. 可能被问到的问题

### Q1: 为什么选择 Flask 而不是 Django？
> Flask 更轻量灵活，适合课程设计的项目规模。Flask 的 Application Factory 模式便于测试和扩展。

### Q2: 排名算法是怎么实现的？
> 采用竞赛排名：分数降序排列，同分同名次，下一个名次跳过。例如 100,100,95,90 对应排名 1,1,3,4。

### Q3: AI 模块如何保证没有 API Key 也能演示？
> 采用策略模式：默认使用 mock 模式，基于真实成绩数据通过规则引擎生成分析结果。预留了 OpenAI-compatible 接口，配置 API Key 即可切换到真实 API。

### Q4: 如何处理并发写入时的统计一致性？
> 成绩写入和统计刷新在同一数据库事务中完成。如果统计刷新失败，整个事务回滚，保证数据一致性。

### Q5: 预警系统为什么不用单独的表？
> 预警数据是基于成绩实时计算的，不需要持久化。这样设计的好处是：成绩更新后预警自动同步，无需额外维护。

### Q6: 前后端如何联调？
> 小程序通过 utils/request.js 统一封装 wx.request，自动拼接 BASE_URL、携带 JWT token 和 trace_id。后端返回统一格式的 JSON 响应。

### Q7: 权限控制是怎么做的？
> 采用简化版 RBAC：用户→角色→权限三级模型。JWT token 中携带用户的角色和权限列表，中间件在请求处理前进行校验。

### Q8: 项目有哪些可以改进的地方？
> 1. 引入 Redis 缓存热点查询
> 2. 使用 Celery 异步处理统计刷新
> 3. 添加单元测试覆盖率
> 4. 实现文件导入成绩功能
> 5. 集成真实 AI API 提升分析质量
