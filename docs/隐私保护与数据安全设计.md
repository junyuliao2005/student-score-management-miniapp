# 隐私保护与数据安全设计

本系统用于 K12 学生成绩管理、家校沟通和学情分析。学生成绩、排名、预警、留言和家长确认记录均属于敏感数据，系统采用“前端提示 + 后端强校验 + 审计留痕”的方式保护隐私。

## 1. 数据保护原则

1. 最小必要：接口只返回当前业务页面需要的数据，不返回密码哈希、token、敏感配置等字段。
2. 后端强校验：前端隐藏按钮不作为安全边界，所有关键接口都通过 JWT、权限或角色中间件再次校验。
3. 数据按角色隔离：学生、家长、教师、管理员四类角色的数据可见范围不同。
4. 已发布才可见：学生端和家长端只展示已发布的成绩，`draft` 和 `withdrawn` 发布记录不可见。
5. 操作可追踪：登录、导入、发布、绑定、签名确认、AI 分析等关键操作写入审计日志。

## 2. 四类角色访问边界

### 学生

- 只能通过 `/api/scores/my` 查看当前登录学生自己的成绩。
- 后端使用 JWT 中的 `current_user.user_id` 作为学生 ID，不信任前端传入的 `student_id`。
- 学生端筛选项 `/api/scores/my/options` 也只从当前学生实际成绩中生成。
- 如果系统启用考试发布机制，学生端只看到适用于自己的 `published` 成绩。

### 家长

- 只能通过 `/api/parents/my-children` 查看当前家长已绑定的孩子。
- 查看孩子成绩前，`/api/parents/children/<student_id>/published-scores` 必须校验 `parent_student_bindings`。
- 家长不能通过修改 URL 中的 `student_id` 查看未绑定学生。
- 家长只能看到 `status='published'` 的发布成绩，`draft` 和 `withdrawn` 不返回。
- 家长签名确认只能确认自己绑定孩子的发布记录，后端不信任前端传入的 `parent_user_id`。

### 教师

- 教师成绩查询、成绩导入、统计分析、预警、AI 班级分析等接口均要求教师或管理员权限。
- 学生和家长没有 `score:read:all`、`score:create`、`stats:read` 等权限，不能调用教师端接口。
- MVP 阶段暂未建立 `teacher_class_bindings` / `teacher_course_bindings` 精细授权表，当前教师端按教师角色开放管理视图。后续可增加教师-班级/课程绑定，进一步缩小教师可见范围。

### 管理员

- 管理员可维护用户、课程、考试发布和家长绑定。
- 管理员关键操作需要审计留痕，便于追踪修改来源。
- 管理端接口仍需登录和权限校验，不能匿名访问。

## 3. 考试发布保护机制

考试发布通过 `exam_publish_settings` 控制成绩是否对学生/家长可见：

- `draft`：未发布，不对学生和家长可见。
- `published`：已发布，可按学期、考试批次、年级、班级匹配后展示。
- `withdrawn`：已撤回，不对学生和家长可见。

发布范围支持：

- 学期：匹配课程 `courses.term`。
- 考试批次：匹配成绩 `scores.exam_batch`。
- 年级：从学生班级解析，例如 `高三(3)班 -> 高三`。
- 班级：匹配学生 `users.class_name`。

“全部年级 / 全部班级 / 空值”表示不限制对应范围，后端会统一归一化处理，避免把“全部班级”误当真实班级。

## 4. 家长绑定防越权机制

家长与学生关系保存在 `parent_student_bindings`：

- 家长访问孩子列表时只查询当前登录家长的有效绑定。
- 家长查看孩子成绩时先校验绑定关系。
- 家长确认成绩时再次校验绑定关系和发布状态。
- 删除或停用绑定不会删除成绩原始数据，只会阻止家长继续访问该学生数据。

## 5. 后端接口权限校验

主要接口保护方式：

- `/api/scores/my`：`jwt_required` + `score:read:self`，后端使用当前登录用户 ID。
- `/api/scores`：`jwt_required` + `score:read:all`，学生/家长不可访问。
- `/api/scores/import/*`：`jwt_required` + `score:create`，学生/家长不可访问。
- `/api/stats/*`：`jwt_required` + `stats:read`，学生/家长不可访问。
- `/api/exam-publish/*`：教师/管理员角色可管理。
- `/api/parents/*`：家长角色可访问，并校验绑定关系。
- `/api/ai/*`：按 AI 功能权限校验。

## 6. 审计日志

系统复用 `audit_log` 表记录关键操作，字段包括：

- `operator_id`
- `action`
- `target_type`
- `target_id`
- `trace_id`
- `detail_json`
- `result_code`
- `created_at`

当前覆盖：

- 登录成功：`auth.login`
- 登录失败：`auth.login_failed`
- 成绩导入确认：`score.import.confirm`
- 学生基础信息导入确认：`user.import.confirm`
- 考试发布创建：`exam_publish.create`
- 考试发布修改：`exam_publish.update`
- 考试发布发布：`exam_publish.publish`
- 考试发布撤回：`exam_publish.withdraw`
- 考试发布删除：`exam_publish.delete`
- 家长绑定新增：`parent_binding.create`
- 家长绑定停用：`parent_binding.disable`
- 家长签名确认：`parent_score.confirm`
- AI 分析调用：`ai.student_advice`、`ai.class_overview`、`ai.exam_analyze`、`ai.exam_analyze_image`、`ai.combined_advice`
- 师生留言创建和已读操作

## 7. AI 学情分析隐私策略

AI 分析遵循最小必要原则：

- Prompt 中学生姓名弱化为“该学生”。
- 班级分析中的学生姓名弱化为“学生A / 学生B”。
- 传给 AI 的主要是学科、分数、排名、班级统计、考点摘要等学习相关数据。
- 使用脱敏函数过滤手机号、身份证、token、API key、password 等敏感文本。
- API Key 只允许通过环境变量配置，不写入前端或代码仓库。
- 当前体验版以 mock 为主，真实 AI 未配置时不会崩溃。

## 8. MVP 限制与后续改进

当前 MVP 已实现角色隔离、发布控制、家长绑定校验和审计留痕。后续可增强：

1. 增加教师-班级/教师-课程绑定表，限制教师只能查看授权班级和课程。
2. 增加更细的管理员操作审批，例如批量删除、批量导入二次确认。
3. 增加隐私导出记录和敏感字段访问审计。
4. 增加接口级自动化越权测试。
5. 对 AI prompt 做更细粒度的字段白名单控制。
